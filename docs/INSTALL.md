# Сборка и установка на два телефона

## 0. Сначала поднимите сервер ⚠️

Приложению **обязательно нужен запущенный сервер** в интернете — без него телефоны не свяжутся и регистрация падает с ошибкой «failed to connect». Адрес по умолчанию пуст: впишите адрес **своего** сервера. **`10.0.2.2` работает только в эмуляторе Android**, на реальном телефоне его указывать нельзя.

- Проще всего развернуть сервер на недорогом VPS по пошаговой инструкции: **[DEPLOY_VPS.md](DEPLOY_VPS.md)** (сначала HTTP, затем HTTPS).
- Для быстрой локальной пробы можно запустить сервер на ПК в той же сети Wi‑Fi (`cd server && npm install --omit=optional && npm start`) и указать в приложении `http://IP-компьютера-в-сети:8080`.

После того как сервер отвечает по адресу `http://ВАШ-АДРЕС:8080/v1/health`, переходите к установке приложения.

## 1. Сборка debug APK

> В облачной среде этого проекта заблокирован доступ к `dl.google.com` (весь Android SDK/Google Maven), поэтому APK здесь не собирается. Варианты ниже собирают его там, где доступ есть.

### Вариант 1 — GitHub Actions (готовый APK без установки инструментов)
1. Положить содержимое `/mnt/project-files/shlagbaum/` в репозиторий (папки `android/` и `server/`).
2. Workflow `.github/workflows/android.yml` на каждый пуш в `main`/`master` собирает debug APK.
3. Открыть вкладку **Actions** → последний запуск → артефакт **shlagbaum-relay-debug-apk** → скачать `app-debug.apk`.

### Вариант 2 — локально (Android Studio / командная строка)
Требуется JDK 17 и Android SDK (platform 34, build-tools). Затем:
```bash
cd android
chmod +x gradlew
./gradlew :app:assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
```
В Android Studio: открыть папку `android`, дождаться синхронизации Gradle, Build → Build APK(s).

## 2. Поднять backend

См. `server/README.md`. Для первого запуска достаточно режима `pull-only` без Firebase:
```bash
cd server && npm install --omit=optional && npm start   # :8080
```
APK по умолчанию обращается к `http://10.0.2.2:8080` (адрес хоста из эмулятора). Для реальных телефонов укажите в приложении адрес, доступный с телефонов: IP вашего ПК в той же сети (`http://192.168.x.x:8080`) или публичный адрес хостинга. Поле «Адрес сервера» — на первом экране приложения.

## 3. Установка на телефоны

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```
или перенести `app-debug.apk` на телефон и установить вручную (включив «установку из неизвестных источников»).

- На **телефоне A**: открыть приложение → указать адрес сервера → «Это пульт (телефон A)».
- На **телефоне B**: открыть приложение → тот же адрес → «Это приёмник (телефон B)».

## 4. Первичная настройка (телефон B)

1. Экран приёмника → добавить шлагбаум: название, метка `barRef`, тестовый номер. Галку «реальный звонок» пока не ставить.
2. Выдать доступ: «Создать код приглашения» → продиктовать 6-значный код на телефон A.
3. Режим приёма: включить «Опрашивать очередь» (и/или настроить FCM, см. ниже). При включении приложение попросит разрешение на уведомления и предложит исключить себя из оптимизации батареи — согласитесь (нужно, чтобы приёмник не убивался).
4. Для реального звонка позже: выдать разрешения на звонок, затем включить «реальный звонок» глобально и для нужного шлагбаума.

## 5. Телефон A

Погасить код на экране пульта → шлагбаум появится в списке → «Открыть». Статусы: отправлено → получено B → запрошен вызов → вызов инициирован (или ошибка/тестовая имитация).

## 6. Настройки выживания сервиса на разных производителях (телефон B)

Чтобы приёмник не убивался системой (особенно для pull и для надёжности FCM):
- **Оптимизация батареи:** Настройки → Батарея → для приложения выбрать «Без ограничений» / исключить из оптимизации.
- **Автозапуск (Xiaomi/MIUI, Huawei, Oppo, Vivo, Realme):** включить автозапуск приложения в фоне в настройках безопасности/запуска оболочки.
- **Фоновая активность:** разрешить «фоновую активность» / «работать в фоне».
- **Samsung:** убрать приложение из «спящих»/«глубоко спящих».

## 7. Включение FCM (рекомендуется для продакшена)

Нужно для надёжного пробуждения при выключенном на минуты экране (сценарий 6 теста).
1. Создать проект Firebase, включить Cloud Messaging; добавить Android-приложение с `applicationId = com.example.shlagbaumrelay`; скачать `google-services.json` в `android/app/`.
2. В `android/build.gradle.kts` добавить в блок plugins:
   `id("com.google.gms.google-services") version "4.4.2" apply false`
3. В `android/app/build.gradle.kts` раскомментировать плагин `com.google.gms.google-services` и зависимости `firebase-bom` + `firebase-messaging-ktx`.
4. Переименовать `app/src/main/java/.../receiver/FcmService.kt.template` → `FcmService.kt` и раскомментировать `<service>` в `AndroidManifest.xml`.
5. На сервере задать `GOOGLE_APPLICATION_CREDENTIALS` (ключ сервис-аккаунта того же проекта Firebase) и перезапустить — `GET /v1/health` покажет `"fcm":"fcm+pull"`.
6. В приложении B включить приём; при получении FCM-токена он сам отправится на сервер.

> Серверный ключ Firebase (`google-services.json` — это клиентский конфиг, а приватный ключ сервис-аккаунта — серверный секрет) в APK **не** кладётся.
