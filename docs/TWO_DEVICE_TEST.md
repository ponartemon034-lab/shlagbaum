# Сценарий проверки на двух физических телефонах

Главный результат проекта — воспроизводимый эксперимент, а не только собирающийся APK. Ниже — пошаговый план для двух реальных телефонов.

> **Статус выполнения:** у меня (в облачной среде) **нет физических телефонов и нет эмулятора с телефонией**, поэтому ни один из сценариев ниже мной **не выполнен**. Ничего не симулирую как «пройдено». Таблица результатов в конце заполнена значением «НЕ ВЫПОЛНЕНО (нет устройств)». Это план для вас.

## Участники

- **Телефон A** — пульт (роль controller). Нужен только интернет.
- **Телефон B** — приёмник (роль receiver), **с SIM-картой** и правом звонить на тестовый номер. Именно он звонит.
- Желательно **два разных интернет-подключения** (например, A по Wi‑Fi, B по мобильному).
- **Тестовый номер.** На первом этапе — безопасный тестовый обработчик (реальный звонок выключен). Реальный номер — только на отдельном этапе, с разрешения владельца номера и по правилам системы.

## Подготовка

1. Поднять backend (см. `server/README.md`). Для первых проверок хватит режима `pull-only` без Firebase. Для сценариев с выключенным на минуты экраном — включить FCM (см. INSTALL.md, раздел «Включение FCM»).
2. Собрать и установить debug APK на оба телефона (см. INSTALL.md).
3. На B: добавить шлагбаум (название, `barRef`, тестовый номер), **оставить реальный звонок выключенным** (безопасный режим), включить «Опрос очереди» (и/или FCM).
4. На B: создать код приглашения, на A — погасить его. Шлагбаум появляется у A.

## Этап 1 — безопасный тестовый обработчик (без реального звонка)

Во всех сценариях ниже сначала проверяем с **выключенным** реальным звонком: B доходит до статуса `COMPLETED (simulated)` — это значит, что команда дошла, прошла все проверки и B инициировал бы вызов. Так проверяется весь путь без фактического звонка.

## Этап 2 — разрешённый реальный вызов

Только после успеха этапа 1: на B включить «реальный звонок» глобально и для конкретного шлагбаума, затем повторить ключевые сценарии (3, 4, 5, 6) с реальным тестовым номером.

## Сценарии (ТЗ п. 11)

Для каждого фиксируйте: ожидаемый результат, фактический результат, время доставки (от нажатия «Открыть» на A до статуса на B), журналы ошибок (`adb logcat | grep Shlagbaum`).

| # | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Оба устройства регистрируются | A и B получают authToken; `health` отвечает |
| 2 | A видит B как привязанный | После погашения кода шлагбаум B виден в списке A |
| 3 | Команда при разблокированном экране B | B: RECEIVED→CALL_REQUESTED→COMPLETED; вызов инициирован |
| 4 | Команда при заблокированном экране B | То же; экран не разблокируется, вызов ставится |
| 5 | Приложение B не на переднем плане | Доставка и вызов работают (foreground-сервис поднимается) |
| 6 | Экран B выключен ≥ несколько минут | С FCM — доходит; с pull — зависит от того, жив ли сервис (ожидаемо менее надёжно) |
| 7 | B временно теряет интернет | Команда остаётся в очереди; после возврата сети B забирает её (pull) или получает повторный push; в пределах `expiresAt` |
| 8 | Повторная доставка той же команды | Второго звонка нет (dedup по commandId на B и на сервере) |
| 9 | Команда просрочена/отозвана | Статус `EXPIRED`/`REVOKED`; звонок не инициируется |
| 10 | Телефон B перезагружен | После загрузки опрос перезапускается (если был включён и ОС доставила BOOT_COMPLETED) |
| 11 | Номер не в allowlist | B: `CALL_BLOCKED (bar_not_in_allowlist)`; звонка нет |
| 12 | Android блокирует автоматический вызов | B фиксирует `CALL_BLOCKED (no_permission/…)`; статус честный, без ложного «открыто» |

## Что проверено без телефонов

- **Серверный сквозной прогон и конечный автомат:** `server/src/selftest.js` — 20 проверок, 0 провалов (регистрация, привязка по коду, DISPATCHED→…→COMPLETED, идемпотентность, anti-replay, expiry, revoke, rate limit, разделение ролей, отсутствие секретов в журнале).
- **HTTP-прогон живого API:** A→команда→B(pending)→ack→COMPLETED, nonce не утекает клиенту.

Эти проверки подтверждают серверную часть и логику состояний; они **не** заменяют проверку звонка и фонового поведения на реальных телефонах (сценарии 3–12).
